# Staged GitHub release plan

## Repository and version rules

- 使用一个公开主仓库；`main` 保持可复现，功能工作在短期分支，通过 PR 合并。
- 软件版本以根目录 `pyproject.toml` 为准，Git tag 为 `vMAJOR.MINOR.PATCH`；原始数据格式有单独 `schema_version`。
- 在公开 `v1.0.0` 前，版本视为迭代接口；破坏数据格式须提供转换脚本并更新 `schema_version`。
- 每个功能 PR 标明旧文件、目标文件、输入输出变化、验证结果和第三方归属。
- 每个发布版本更新 `CHANGELOG.md`、文档、依赖锁定信息，打 tag 并在 GitHub Release 写明设备和系统要求。

每阶段分多个小 PR：接口与配置 → 实现 → 离线测试 → 硬件验证 → 文档与发布。先上传已验证部分，后续模块独立演进。模型权重和真实录制数据不随代码推送。

旧项目代码曾在真机运行；本轮重组只有离线环境。可以分版发布经过假设备或合成旧格式测试的**预发布代码**，但必须写明历史真机使用与当前版本复测的区别，不能将二者混同。实时采集、回放和控制的当前硬件验收记录仍待补；每版先测试、后合并与发布。

`v0.1.0` 只满足 P1 的离线回归、合成示例和安装说明部分，发布为 **pre-release**；表中的“真机数据人工核对”尚未满足，不能将其称为硬件验收后的稳定版本。获得设备或脱敏录制后需补真实 Topic、时钟、单位、图像与动作来源对照记录。

`v0.2.0` 只满足 P2 的合成 ROS2 消息回放、只读采集入口及相机映射离线回归，作为 **pre-release** 发布。动作来源、关节和夹爪物理单位、真机安全检查尚未确认，因此不实现旧 HDF5→`RobotCmd` 运动回放；真机验收门槛仍未满足。

`v0.3.0` 的自有 HDF5 已用同一合成 Episode 实际写入/读回；LeRobot 导出路径只用注入式 API 假对象完成写入/读回，真实 LeRobot 包和 OpenPI/LLaMA-Factory 模型数据加载尚未验收。因此仅作为 **pre-release** 上传，P3 的“模型数据加载成功”仍未满足。

`v0.4.0` 提供四种模型形状的注入式推理客户端及无命令发布的离线动作安全预览。超时测试只拒绝**返回过晚**的结果，不能中断阻塞的真实模型调用；急停只锁定本地 runner，不是设备急停。真实模型输入预处理、设备安全状态和真机演示均未验收，因此作为 **pre-release** 上传，P4 的真机门槛仍未满足。

`v0.5.0` 只复现两个合成任务的“假语音/文本→假 VLM 白名单提议→人工批准→假 VLA 离线预览”链路；本机 Web 没有执行端点。真实语音、VLM/VLA 服务、旧 MagicBot GUI 的缺失模块、实时并发停止和完整真机任务均未验收，因此作为 **pre-release** 上传，P5 的真实任务门槛仍未满足。

`v0.6.0` 已把 P6 中的旧数据导入、控制适配和数据预处理收拢为离线可复现功能。该版用真实旧 ARX 示例文件验证 140 个状态导入、139 个 next-state 样本导出和 4 路相机标定读回；视频解码使用注入式假后端测试，真实 OpenCV 编解码待 CI/环境验证。此版作为 **pre-release**；真机安全、模型闭环和硬件验收仍未满足。

`v0.7.0` 完成模型端到端适配，要求针对真实 checkpoint 校验观察键、图像通道、动作维度和归一化统计；没有可分发权重时，通过外部路径注入验证，仓库不保存权重。

`v0.8.0` 完成旧项目自有操作流程的代码迁移，旧 Qt/网页界面按新架构重建；VR SDK、机器人驱动等上游依赖独立安装。发布标签标明离线验证与硬件验收状态。

## First upload sequence

1. 本地完成 P0 清单并确认项目代码许可证及第三方使用方式。
2. 在 GitHub 创建空仓库，开启分支保护、PR 审查和基本 CI。
3. 推送 P0 的精简仓库，发布 `v0.0.1`，明确它只提供公共接口。
4. 后续每个阶段通过 PR 合并与 Release 发布；未完成的阶段放在 Issues/Milestones 中跟踪。

公开文件和许可证确认后，在新仓库执行以下步骤。把占位符替换成实际 GitHub 所有者和仓库名；`git add --dry-run .` 可先复核文件集合。创建公开仓库前不要导入旧项目历史。

```bash
git add .
git diff --cached --stat
git commit -m "chore: establish public project foundation"
git remote add origin git@github.com:<owner>/<repository>.git
git push -u origin main
git tag -a v0.0.1 -m "Foundation and public roadmap"
git push origin v0.0.1
```

后续版本在发布 PR 中更新 `pyproject.toml` 与 `CHANGELOG.md`，合并后从 `main` 打同号 tag。若公开前发现敏感信息进入 Git 历史，不仅删除工作区文件，还需处理历史并轮换受影响的凭据。
